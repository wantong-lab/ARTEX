# C2 管理页信息架构与文案优化（v0.4.9）

## 背景

C2 页面同时承载：平台监听器、入站中继、植入端生成、会话、任务。字段多、术语集中（chisel、listener、beacon、VPS 会话），新用户很难判断“目标该走哪条路、每个字段是什么意思”。

## 目标

- 首屏先回答“两种使用方式选哪个”；
- 字段按任务顺序编排，并给出默认值/解释；
- 不改变任何后端接口、数据和部署语义。

## 非目标

- 不重构 C2 后端；
- 不新增配置项；
- 不替代 docs/c2-ingress-runbook.md 的详细排障。

## 信息架构

1. 状态与授权提示；
2. “先看这里：两种使用方式”说明卡：
   - 方式 A：目标能直接访问平台 → 监听器 + 植入端；
   - 方式 B：目标只能访问 VPS → 入站中继；
   - 字段速查表（可折叠）。
3. 平台监听器（先创建/确认）；
4. 入站中继（按场景 B 使用）；
5. 植入端生成；
6. 会话；
7. 任务。

## 文案与交互

- 卡片标题加序号和使用条件；
- 字段标签写“人话”，专业词放括号/说明；
- 入站中继默认端口改为 39444，平台 chisel 默认 39443；
- 高级字段（平台 host/port、节点标签、语言）集中说明，避免首屏压迫；
- 保留现有按钮/接口行为。

## 验收

- web build 通过；
- 首屏无需展开文档即可判断两种方式；
- 监听器/中继/植入端/会话/任务顺序清晰；
- 不改变 API 请求体与后端逻辑。

## 实施记录（v0.4.9）

- 首屏新增“先看这里：选哪种方式？”卡：方式 A（目标直连平台）/方式 B（目标只访问 VPS）+ 可折叠字段速查。
- 卡片顺序调整为：平台监听器 → 入站中继 → 植入端 → 会话 → 任务，并加 ①-⑤ 序号。
- 入站中继默认回调端口改为 39444，平台 chisel 默认 39443；字段标签改成人话并加解释。
- 没有改后端接口、数据模型或请求体。
